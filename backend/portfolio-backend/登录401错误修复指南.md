# 登录 401 错误修复指南

## 问题分析

从错误信息看，前端请求的 URL 是：
```
POST http://localhost:5173/api/auth/login 401 (Unauthorized)
```

这个 URL 有问题！`localhost:5173` 是前端开发服务器的地址，不是后端地址。

## 解决方案

### 方案 1：修复前端 API 配置（推荐）

前端应该请求后端地址 `http://localhost:8080/api/auth/login`

**如果使用 axios：**

```javascript
// auth.ts 或 api.ts
import axios from 'axios';

const api = axios.create({
  baseURL: 'http://localhost:8080',  // 后端地址
  withCredentials: true  // 重要：允许发送 Cookie（Session）
});

// 登录请求
export const login = async (username: string, password: string) => {
  const response = await api.post('/api/auth/login', {
    username,
    password
  });
  return response.data;
};
```

**如果使用 Vite 代理：**

在 `vite.config.js` 中配置代理：

```javascript
export default {
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',  // 后端地址
        changeOrigin: true,
        secure: false
      }
    }
  }
}
```

然后前端请求时使用相对路径：

```javascript
// 使用相对路径，会被代理到后端
const response = await axios.post('/api/auth/login', {
  username,
  password
}, {
  withCredentials: true
});
```

### 方案 2：更新数据库密码为明文

如果数据库中的密码还是 BCrypt 加密的，需要更新为明文：

```sql
-- 更新测试用户密码为明文 '123456'
UPDATE users SET password = '123456' WHERE username IN ('user001', 'staff001', 'auditor001', 'admin');

-- 验证更新结果
SELECT username, password FROM users WHERE username IN ('user001', 'staff001', 'auditor001', 'admin');
```

### 方案 3：重新插入测试用户

如果数据库中没有用户或需要重新创建：

```sql
-- 删除旧数据
DELETE FROM users WHERE username IN ('user001', 'staff001', 'auditor001', 'admin');

-- 插入新数据（明文密码）
INSERT INTO users (username, password, email, role, status, created_at, updated_at) VALUES
('user001', '123456', 'user001@example.com', 'USER', 1, NOW(), NOW()),
('staff001', '123456', 'staff001@example.com', 'STAFF', 1, NOW(), NOW()),
('auditor001', '123456', 'auditor001@example.com', 'AUDITOR', 1, NOW(), NOW()),
('admin', '123456', 'admin@example.com', 'AUDITOR', 1, NOW(), NOW());
```

## 完整排查步骤

### 步骤 1：检查后端服务是否运行

```bash
# 确保后端服务在 8080 端口运行
# 访问 http://localhost:8080/api/auth/login 应该返回 400（参数错误）而不是 404
```

### 步骤 2：检查前端 API 配置

检查 `auth.ts` 文件，确保：
- 使用正确的后端地址（`http://localhost:8080`）
- 或者配置了正确的代理

### 步骤 3：检查数据库

```sql
-- 检查用户是否存在
SELECT id, username, password, role, status FROM users WHERE username = 'user001';

-- 确保：
-- 签约业务模块设计.md. 用户存在
-- 2. password 是明文 '123456'（不是 BCrypt 加密的）
-- 3. status = 签约业务模块设计.md（正常状态）
```

### 步骤 4：使用 Postman 测试

直接测试后端接口：

```
POST http://localhost:8080/api/auth/login
Content-Type: application/json

{
  "username": "user001",
  "password": "123456"
}
```

如果 Postman 测试成功，说明后端正常，问题在前端配置。

### 步骤 5：检查浏览器控制台

查看 Network 面板：
- 请求的完整 URL 是什么？
- 请求是否发送到了正确的后端地址？
- 响应内容是什么？

## 常见错误

### 错误 1：请求发送到前端地址

**现象：** `POST http://localhost:5173/api/auth/login`

**原因：** 前端没有配置代理或 API baseURL 配置错误

**解决：** 配置 Vite 代理或修改 API baseURL

### 错误 2：CORS 错误

**现象：** 浏览器控制台显示 CORS 相关错误

**原因：** 后端 CORS 配置不包含前端地址

**解决：** 检查 `CorsConfig.java`，确保包含 `http://localhost:5173`

### 错误 3：密码验证失败

**现象：** 后端返回 "用户名或密码错误"

**原因：** 数据库中的密码是 BCrypt 加密的，但代码已改为明文比较

**解决：** 执行 SQL 更新密码为明文
