# 登录 401 错误排查指南

## 问题现象

前端调用登录接口时返回 `401 Unauthorized` 错误。

## 可能的原因

### 1. 数据库中没有用户数据

**解决方法：** 执行测试用户插入脚本

```sql
-- 执行文件：src/main/resources/sql/insert_test_users.sql
```

**测试账号：**
- 用户名：`user001`，密码：`123456`，角色：普通用户
- 用户名：`staff001`，密码：`123456`，角色：工作人员
- 用户名：`auditor001`，密码：`123456`，角色：审核人员
- 用户名：`admin`，密码：`123456`，角色：审核人员

### 2. 密码加密方式不匹配

如果数据库中的密码不是 BCrypt 加密的，会导致密码验证失败。

**解决方法：** 使用以下 Java 代码生成 BCrypt 密码：

```java
import org.mindrot.jbcrypt.BCrypt;

public class PasswordGenerator {
    public static void main(String[] args) {
        String password = "123456";
        String hashedPassword = BCrypt.hashpw(password, BCrypt.gensalt());
        System.out.println("原始密码: " + password);
        System.out.println("BCrypt 加密后: " + hashedPassword);
    }
}
```

然后更新数据库中的密码：

```sql
UPDATE users SET password = '生成的BCrypt密码' WHERE username = 'user001';
```

### 3. 用户状态不正确

用户状态必须是 `1`（正常），如果是 `0`（禁用）会导致登录失败。

**检查方法：**

```sql
SELECT id, username, status, role FROM users WHERE username = 'user001';
```

**修复方法：**

```sql
UPDATE users SET status = 1 WHERE username = 'user001';
```

### 4. 数据库连接问题

检查数据库连接配置是否正确：

```properties
# application.properties
spring.datasource.url=jdbc:mysql://116.62.82.244:3306/wealthadvisor?allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=Asia/Shanghai
spring.datasource.username=remote_admin
spring.datasource.password=123456
```

### 5. 用户表不存在

确保已执行用户表创建脚本：

```sql
-- 执行文件：src/main/resources/sql/user_auth_schema.sql
```

## 排查步骤

### 步骤 1：检查用户表是否存在

```sql
SHOW TABLES LIKE 'users';
```

如果表不存在，执行 `src/main/resources/sql/user_auth_schema.sql`

### 步骤 2：检查是否有用户数据

```sql
SELECT * FROM users;
```

如果没有数据，执行 `src/main/resources/sql/insert_test_users.sql`

### 步骤 3：检查特定用户

```sql
SELECT id, username, password, role, status FROM users WHERE username = 'user001';
```

确保：
- `status = 1`（正常状态）
- `password` 是 BCrypt 加密的（以 `$2a$` 开头）

### 步骤 4：测试密码验证

使用以下 SQL 查询验证密码格式：

```sql
-- BCrypt 密码应该以 $2a$ 开头
SELECT username, 
       CASE 
           WHEN password LIKE '$2a$%' THEN 'BCrypt格式正确'
           ELSE '密码格式错误'
       END AS password_format
FROM users;
```

### 步骤 5：查看后端日志

启动后端服务，查看控制台输出的错误信息：

```bash
mvn spring-boot:run
```

登录时查看是否有异常信息，例如：
- `用户名或密码错误`
- `用户已被禁用`
- 数据库连接错误

### 步骤 6：使用 Postman 测试

使用 Postman 直接测试登录接口：

```
POST http://localhost:8080/api/auth/login
Content-Type: application/json

{
  "username": "user001",
  "password": "123456"
}
```

查看返回的具体错误信息。

## 常见错误信息

### "用户名或密码错误"

可能原因：
1. 用户名不存在
2. 密码不正确
3. 密码加密方式不匹配

解决方法：
1. 检查用户名是否正确
2. 确认密码是 `123456`
3. 重新插入测试用户数据

### "用户已被禁用"

可能原因：用户状态 `status` 不是 `1`

解决方法：
```sql
UPDATE users SET status = 1 WHERE username = 'user001';
```

### 数据库连接错误

可能原因：
1. 数据库地址不正确
2. 数据库用户名/密码错误
3. 数据库服务未启动

解决方法：检查 `application.properties` 中的数据库配置

## 快速修复

如果以上步骤都检查过了，可以尝试：

1. **重新插入测试用户：**

```sql
-- 删除旧数据
DELETE FROM users WHERE username IN ('user001', 'staff001', 'auditor001');

-- 插入新数据（使用正确的 BCrypt 密码）
INSERT INTO users (username, password, email, role, status, created_at, updated_at) VALUES
('user001', '$2a$10$N.zmdr9k7uOCQb376NoUnuTJ8iAt6Z5EHsM8lE9lBOsl7iwy8pLKO', 'user001@example.com', 'USER', 1, NOW(), NOW()),
('staff001', '$2a$10$N.zmdr9k7uOCQb376NoUnuTJ8iAt6Z5EHsM8lE9lBOsl7iwy8pLKO', 'staff001@example.com', 'STAFF', 1, NOW(), NOW()),
('auditor001', '$2a$10$N.zmdr9k7uOCQb376NoUnuTJ8iAt6Z5EHsM8lE9lBOsl7iwy8pLKO', 'auditor001@example.com', 'AUDITOR', 1, NOW(), NOW());
```

2. **重启后端服务：**

```bash
# 停止当前服务（Ctrl+C）
# 重新启动
mvn spring-boot:run
```

3. **清除浏览器 Cookie：**

如果前端使用了 Session，清除浏览器 Cookie 后重新登录。

## 验证登录是否成功

登录成功后，应该返回：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "id": 1,
    "username": "user001",
    "email": "user001@example.com",
    "phone": null,
    "role": "USER",
    "roleName": "普通用户"
  }
}
```

如果仍然返回 401，请检查后端控制台的详细错误信息。
